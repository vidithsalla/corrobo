# Architecture

corrobo is a small runtime for one dangerous boundary: an external side effect whose transport result may lie by omission. The lifecycle as the code runs it is: [`src/core/runtime.ts`](../src/core/runtime.ts) `runEffect` resolves a string or object identity with `resolveRequest`, reads and fingerprints the intent once with `prepareIntent`, takes the non-blocking per-identity lock with `tryAcquireLock`, and then `runCoordinated` either creates or reuses the operation record. Every new attempt goes through `checkThenAttempt`, which runs the contract's `revalidate()` (if any) and then calls `performAttempt` only on `proceed`; `performAttempt` persists a `RESERVED` attempt before `execute`; unresolved reservations go through `recoverReservedAttempt`, which observes but does not execute; `PENDING` and delayed retry settlement go through `reObserve`; and the `RETRY` path executes again only after settlement has been checked and still says settled `NOT_APPLIED`.

## Module map

- [`src/core/types.ts`](../src/core/types.ts): the public model: identities, contracts, evidence states, dispositions, attempts, operation records, requests, and results. Exported from `corrobo`.
- [`src/core/store.ts`](../src/core/store.ts): the public store contract, including `EffectStore`, `CoordinatedStore`, `OperationLock`, and `StoreConflictError`. Exported from `corrobo`.
- [`src/core/runtime.ts`](../src/core/runtime.ts): the internal coordinator and safety lifecycle. Only `runEffect` is public.
- [`src/core/disposition.ts`](../src/core/disposition.ts): pure evidence-to-disposition mapping. `decideDisposition` and its types are public.
- [`src/core/fingerprint.ts`](../src/core/fingerprint.ts): intent materialization and canonical fingerprints. `canonicalStringify` and `fingerprintIntent` are public; `materializeIntent` is internal.
- [`src/core/helpers.ts`](../src/core/helpers.ts): public ergonomic helpers: `defineContract`, `observed`, and `reconciled`.
- [`src/stores/memory.ts`](../src/stores/memory.ts): `InMemoryStore`, exported from `corrobo`, for tests and single-process local use only.
- [`src/stores/postgres.ts`](../src/stores/postgres.ts): `PostgresStore`, `POSTGRES_SCHEMA_SQL`, and structural `Pg*` types, exported from `corrobo/postgres`.
- [`src/testing/faults.ts`](../src/testing/faults.ts): public deterministic fault helpers under `corrobo/testing`.
- [`src/testing/conformance.ts`](../src/testing/conformance.ts): public conformance harness under `corrobo/testing`.

## The invariants

1. Persist identity and intent, then reserve the attempt, before any external execution. Why: a record with no attempt is treated as never attempted, so that state must only be possible *before* `execute()` starts; otherwise a crash mid-call would make the restart execute again. Enforced in `runtime.ts` `runCoordinated` and `performAttempt`, with store support in `reserveAttempt`. Proved by matrix rows 2.1, 2.2, and tests [`tests/postgres-crash-recovery.test.ts`](../tests/postgres-crash-recovery.test.ts) "a reserved attempt exists before execute() is ever called" and [`tests/runtime.test.ts`](../tests/runtime.test.ts) "persists operation identity and intent before execute() runs, even if execute() throws".

2. `execute()` is never called from `PENDING`, `UNKNOWN`, `CONFLICTED`, `APPLIED`, `REVIEW`, or `CLOSED`. Why: those states either need observation, investigation, replanning, approval, or no work at all; replaying would risk duplicates or a false fix. Enforced in `runtime.ts` `runCoordinated`, `statusAfter`, and `reObserve`, plus `disposition.ts` `decideDisposition`. Proved by rows 3.1, 4.1, 5.1, 6.4, 6.5, 7.1, and tests [`tests/runtime.test.ts`](../tests/runtime.test.ts) "PENDING triggers re-observation on the next call, never a second execute()", "a failed observation is UNKNOWN, never conflated with NOT_APPLIED, and does not silently retry", "CONFLICTED leads to REPLAN and closes the operation (a new identity is needed, not a retry of this one)", and "does not re-execute once the same operation identity is closed".

3. Only a settled `NOT_APPLIED` may retry. Why: a request with failed or unknown transport can still land, so absence before `maxInFlightMs` is not proof. Enforced in `disposition.ts` `decideDisposition` and `decideRetry`, and in `runtime.ts` `runCoordinated`'s `RETRY` branch, `safetyNow`, and `reObserve`. Proved by rows 1.3-1.6 and 6.1-6.4, and tests [`tests/fencing-adversarial.test.ts`](../tests/fencing-adversarial.test.ts) "returns cached RETRY before retryNotBefore without executing or observing", "catches a late landing with the settlement observation before starting a retry", and "retries immediately when transport ok:true proves the request is no longer in flight".

4. Crash recovery observes, never executes, an unresolved reserved attempt. Why: the previous process may have called the provider and died before saving the outcome. Enforced in `runtime.ts` `recoverReservedAttempt`. Proved by rows 2.2-2.6 and tests [`tests/postgres-crash-recovery.test.ts`](../tests/postgres-crash-recovery.test.ts) "crash after the effect occurred but before resolution: restart observes first, finds APPLIED, does not re-execute" and "crash + observation cannot resolve either way: honestly UNKNOWN / INVESTIGATE, no blind re-execution".

5. Every store write is version-checked, and `StoreConflictError` means this pass lost ownership. Why: a lock can disappear while an old `execute()` is still running; stale writes must not overwrite fresher truth. Enforced in `store.ts` `StoreConflictError`, `memory.ts` `write`, `postgres.ts` `versionedWriteResult` and the `*Impl` writes, and `runtime.ts` `runEffect` conflict handling. Proved by rows 8.7 and 8.8, and tests [`tests/postgres-fencing.test.ts`](../tests/postgres-fencing.test.ts) "the lock session is killed mid-execute: no duplicate external effect, and the stale pass never overwrites" and [`tests/fencing-adversarial.test.ts`](../tests/fencing-adversarial.test.ts) "fences every store write with version and reports StoreConflictError metadata".

6. Safety timing uses one clock. Why: host clock skew must not shorten or lengthen the settlement window across processes. Enforced in `runtime.ts` `safetyNow`, `performAttempt`, `recoverReservedAttempt`, and the `RETRY` branch; `postgres.ts` `nowImpl` uses `clock_timestamp()`. Proved by row 8.10 and tests [`tests/fencing.test.ts`](../tests/fencing.test.ts) "attempt start and window checks use the store's clock, not the local one" and [`tests/postgres-fencing.test.ts`](../tests/postgres-fencing.test.ts) "now() reads the database server's clock".

7. Evidence and disposition stay separate; `decideDisposition` is the only mapping. Why: conflating "what happened" with "what next" turns weak evidence into unsafe action. Enforced in `types.ts`, `runtime.ts` `resolveAttempt`, and `disposition.ts` `decideDisposition`. Proved by rows 3.1, 4.1, 5.1, and 6.4, and tests [`tests/disposition.test.ts`](../tests/disposition.test.ts) "UNKNOWN cannot be configured into RETRY — retryOnNotApplied only affects NOT_APPLIED" and "settlement never affects the other evidence states".

8. Identity binds to operation type and the single materialized intent reading. Why: reusing an id for a different effect must throw, not return someone else's cached result. Enforced in `runtime.ts` `resolveRequest`, `prepareIntent`, and `assertSameLogicalOperation`, and `fingerprint.ts` `materializeIntent` and `fingerprintIntent`. Proved by rows 9.1, 9.2, 9.10, and 9.11, and tests [`tests/identity-binding.test.ts`](../tests/identity-binding.test.ts) "same identity + different operationType -> loud conflict error, no execute" and [`tests/fingerprint.test.ts`](../tests/fingerprint.test.ts) "a custom fingerprintIntent takes responsibility: corrobo does not apply the default rules to that intent".

9. `PostgresStore` never persists `error.raw`. Why: raw thrown objects often contain headers, request bodies, SDK clients, or customer data. Enforced in `postgres.ts` `sanitizeAttemptForPersistence`, `sanitizeTransportForPersistence`, and `sanitizeObservationForPersistence`. Proved by row 10.1 and tests [`tests/postgres-error-sanitization.test.ts`](../tests/postgres-error-sanitization.test.ts) "a transport error's raw object never reaches persisted Postgres JSON" and "an observation error's raw object never reaches persisted Postgres JSON".

10. The library source has no logging, telemetry, or network code except `PostgresStore` using the caller's pool, and the package has zero runtime dependencies. Why: corrobo should not create hidden data paths or install-time behavior. Enforced by keeping `src/core` pure and `postgres.ts` structural over `PgPool`. Proved by rows 12.1-12.3 and tests [`tests/failure-catalog.test.ts`](../tests/failure-catalog.test.ts) "no logging of any kind in src/ (application payloads are never printed by corrobo)", "no network-capable code in src/ except PostgresStore's use of the pool you pass in", and "package.json declares no install-time scripts and no runtime dependencies (pg is an optional peer)".

11. `InMemoryStore` is process-local. Why: a restart loses the operation record and therefore the duplicate-prevention memory. Enforced by `memory.ts` storing records and locks in instance fields only. Proved by rows 2.9 and 10.6 and test [`tests/failure-catalog.test.ts`](../tests/failure-catalog.test.ts) "InMemoryStore is process-local: a new instance (a restarted process) has none of the old records".

12. `revalidate()` gates only new attempts, and runs before the reservation. Why: a check that runs after `reserveAttempt` and says no would leave a reserved attempt that recovery must treat as an unknown outcome; and a check that could block observation would let a policy change hide a late landing. Enforced in `runtime.ts` `checkThenAttempt` (the only caller of `performAttempt`) and `runRevalidate` (anything but a valid result fails closed), with `continueOpen` running settlement before it. Proved by rows 7.5–7.13 and tests [`tests/revalidate.test.ts`](../tests/revalidate.test.ts) "runs once, before the attempt is reserved, with the attempt number, this call's context and the record", "a late landing found by the settlement check is APPLIED, and revalidate() is never asked about it" and "a throw: nothing executed or reserved, the operation stays OPEN with REVALIDATION_FAILED, and a later call checks again".

13. A review decision is attributable and bound, and an approval is checked before every attempt it allows. Why: in an agent runtime the approval is the safety boundary; an unattributed flag, an approval of something other than what runs, or a stale approval would each let an effect through that no one actually authorized. Decisions arrive only through `reviewEffect`, which never executes and accepts a decision only for the current review episode (`openReviewEpisode` mints a token each time the operation goes to review; a stale token or a `decidedAt` before the episode began is refused); `runEffect` takes no decision (`refuseReviewDecision` throws on 0.3's field). Enforced in `runtime.ts` `parseReviewDecision` (malformed decisions throw before anything runs), `recordReview` (binds to the recorded intent's fingerprint, refuses mismatches and already-expired approvals) and `checkApproval` (run by `checkThenAttempt` before `revalidate()`). Proved by rows 7.14–7.22 and tests [`tests/review-approval.test.ts`](../tests/review-approval.test.ts) "an approval made for a different intent than the recorded one is refused, and nothing changes" and "an approval that expires before a later attempt sends it back to review instead of executing".

## Change checklist

- New evidence state or disposition: update `types.ts`, `disposition.ts`, runtime result handling, [v0.1 spec](v0.1-spec.md), [failure matrix](failure-matrix.md), and exact test citations.
- New store: implement `tryAcquireLock`, version-checked writes, `StoreConflictError`, optional shared `now()`, conformance-style crash and concurrency tests, and persistence/privacy documentation.
- New store write: add `expectedVersion`, conflict behavior, unchanged-on-failure tests, and a matrix row if it changes a failure boundary.
- Runtime path changes: add or update a [failure matrix](failure-matrix.md) row and a test title citation; `failure-matrix-doc` and `docs-links` will police the docs.
- New public export: update `package.json` exports if needed, [`CHANGELOG.md`](../CHANGELOG.md), README/consumer examples, and the compatibility story.
- Anything persisted: update privacy docs, Postgres sanitization tests if `error.raw`-like data appears, and retention/acknowledgement wording.

## Proof machinery

[`tests/failure-matrix-doc.test.ts`](../tests/failure-matrix-doc.test.ts) requires every matrix row to cite real listed tests and every listed test to exist under its exact title. [`tests/docs-links.test.ts`](../tests/docs-links.test.ts) checks relative links in the README, `CONTRIBUTING.md`, `CHANGELOG.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` and `docs/*.md`, including GitHub-style anchors. [`tests/quickstart.test.ts`](../tests/quickstart.test.ts) keeps the README quickstart equal to `examples/quickstart/quickstart.ts` and runs it. The timeout demo tests and CI command prove the headline ledger behavior; `npm run conformance` and [`tests/conformance-known-bad.test.ts`](../tests/conformance-known-bad.test.ts) prove the harness accepts good contracts and rejects known-bad ones; the DBOS example is also CI-gated across a real `SIGKILL` between an external write and workflow checkpoint.
